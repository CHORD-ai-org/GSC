一、背景与决策

GSC 已完成 P0–P6 与 P1/P2 全部执行项（vitest 135/135 全绿），核心信息模型（Raw/Object 混合模型、提案→确认制、关系表、溯源）稳定。Malleable Context Space 跨项目研究（Ream、CLEO、Interaction-Process-Infrastructure、Malleable Workspace、Inkitiate 五路论文）给出方向：把「表征→就地操作→归因变更→互相看见→反思改结构」做成一套工作台基底，对琐碎工作优雅降级为普通列表与对话。

  创始人决策（DECIDED，2026-11-22）：GSC 要包含多种视角，同时具备 Ream 的感觉（参与痕迹局部可视化、双向可读的互知意识）与 Huabu 的感觉（空间工作台：选择/圈定即上下文边界、显式委派）。View 是投影不是数据模型（D-079 纪律延续）；机器产物确认前永远是提案（D-042）。

二、总体路线

五个可独立验收的垂直切片按序推进：V1 痕迹层 → V2 多投影切换 → V3 归因与提案面 → V4 空间工作台（依赖 Q-E 拍板）→ V5 场景闭环验证。其中 V4 可与 V3 并行，其余串行。全程遵守四条底线：不为投影建表、不做向量库与图数据库、不做无限画布、不做自动抽取与自动结构重组。

数据基础优先于界面：V1 的事件归因是 V2 时间线、V3 归因条、V5 留证脚本的共同地基；V2 的「切换零副本」断言方法被 V4 沿用。

三、V1 痕迹层 —— 「谁动过什么」可见（M1）

（一）目标

具体场面：打开「原始信息」列表，每行右侧有一对蓝/橙横条，蓝=你的活动量、橙=Agent 的活动量，条长即活动量。点进任一条目，详情页显示「你 2 次 · Agent 5 次 · 最近改动 10:22」，最近动作一句话可见。痕迹随使用逐条积累（Ream 的「计算磨损」感）。

四、V2 多投影切换 —— 一份表征，多种投影（M2）

（一）目标

具体场面：同一批对象在列表顶部一键换投影——列表（扫读）、阅读（原文）、关系（连线）、时间线（事件排布）、空间（编排）。切到时间线看到「11-19 概念确认 / 11-20 H1 派生」，切到关系看到 supports 与 derived_from 连线（提案中的边画虚线）。任何切换都不改动数据；常用筛选可「保存当前筛选」。

八、不做清单（全程有效）

第一，不为视图/投影建存储表；空间邻近不等于语义关系，显式边为准。第二，不做向量库、图数据库、无限画布、自动抽取、自动结构重组。第三，机器产物永远走提案（D-042）；痕迹权限沿用 owner/share（GAP-15 不在本期）。第四，过程模型（P/W/O/E/R）、passage 级痕迹、墨迹、跨项目协议一律后置到后续阶段。

九、执行前确认点

第一，Q-E 档位：表征分 scratch / kept 两档先行（canonical 照旧走 Context / Cluster），是否同意。第二，顺序：V1→V2→V3→V4（V4 可与 V3 并行），是否同意。第三，验收方式：逐里程碑（M1–M5）验收，还是全部完成后一次验收。
