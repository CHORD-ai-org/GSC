# Malleable Context Space — 千字摘要

**问题**：GSC / Thylas / Lemma 三方在解同一道题——人与 Agent 共同工作时，"正在做的工作"以什么形态存在、被谁看见、如何演化。本研究核实五篇论文（Ream、CLEO、Interaction-Process-Infrastructure、Malleable Workspace、Inkitiate，后三者属 Huabu / MSRA 一系），提炼可共享的概念基底。供创始人研讨，不是架构决策。

**五路结论**

1. **表征即工作对象**（Malleable Workspace，摘要级）：人与 Agent 形成并修订"工作表征"（单元＋关系＋编排）来推进工作；结构在使用中长成，不应预先设计死。58 篇综述发现：系统普遍只肯把 Agent 产出"局部纳入"，回避结构重组——所以 Agent 改结构必须走提案，不能直接动手。
2. **归因是枢纽**（CLEO，全文级）：可见性不等于协作。Agent 分不清用户的并发编辑是"反馈"还是"独立工作"，就会误改、误还原，用户随即停止介入。需要编辑级归因词汇：反馈 / 并行 / 共创 / 接管 / 复用，且各有不同应对。
3. **痕迹双向可读**（Ream，摘要级）：参与痕迹附在工作对象上，人用它检视证据与方向，Agent 用它接续前人工作——同一份记录服务两个方向。
4. **选择即上下文边界**（Inkitiate，全文级）：选中什么、圈住什么，就是给 Agent 的任务边界；须显式提交才行动；结果落为持久、可编辑、可再用的对象。
5. **过程可显式化但有代价**（IPI，全文级）：目标 / 流程 / 操作 / 环境 / 反思可做成可检视可编辑的表征，但建模有开销——琐碎工作不要上。

**合成**：五篇连成一个循环——表征 → 就地操作 → 归因变更 → 互相看见 → 反思改结构。每篇只解一段；"Malleable Context Space"主张把这整个循环做成同一套基底，且对琐碎工作优雅降级为普通列表与对话。

**最强共享原型**：Thylas 的"一个制品、一个权威、多处引用，以提案达成一致"与 GSC 的提案→确认制是同一个协议，双方独立发明。可共享候选：提案协议、带溯源的类型化对象、表征＝引用集、参与痕迹、上下文边界、归因词汇。

**必须保持分开**：GSC＝跨工作区信息治理；Thylas＝Coworker 与 Artifact 权威版本；Lemma＝认知状态与教学法（掌握度、误区、成长不入共享模型）。关键未决：Lemma 的概念图是"理解的表征"还是"被治理的信息"。

**冲突（未擅自合并）**：Artifact 版本固定制 vs GSC supersede 链；GSC"不自动抽取"铁律 vs Agent 结构重组方向；过程一等实体 vs"不乱建表"纪律。

**待创始人裁决**：空间是视图还是环境；过程建模形态（一等实体 / 事件派生 / 混合）；CHORD↔Lemma 共享到哪一层（概念 / 规范 / SDK）；表征持久化三档（scratch / kept / canonical）取舍；先试点哪个场景（建议 GSC 最小验证：选中 N 条 → 委派 → 结果走提案）。

**局限**：Ream 与 Malleable 仅摘要级；CLEO 数据两版本不一致（模式可靠、比率存疑）；IPI 未经纵向验证；跨工作区治理无文献覆盖。
